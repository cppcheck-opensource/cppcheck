Infrastructure & dependencies:
- Added arm64 platform files arm64-windows.xml, arm64-linux.xml and arm64-macos.xml (Apple Silicon).
  These describe the default setup for that OS. The arm64-wchar_t2.xml and arm64-wchar_t4.xml files are kept.
- The rules feature (HAVE_RULES) now uses PCRE2 instead of the discontinued PCRE library. On Windows the
  Visual Studio project now expects pcre2-8.lib and pcre2.h in externals.
- The QtCharts dependency has been removed from the GUI, and with it the History tab in the statistics dialog.
  The GUI no longer writes statistics.txt to the build dir. The WITH_QCHART CMake option is deprecated and has
  no effect.

Other:
- Iterators of non-template library containers (e.g. std::string::iterator, std::string_view::const_iterator, QString::iterator, wxString::iterator) are now detected as iterators.
  Previously such variables had no value type, so several iterator checks (e.g. containerOutOfBounds, mismatchingContainerIterator) missed bugs involving them.
- Iterators of std::span and gsl::span (e.g. std::span<int>::iterator) are now detected as iterators instead of containers, and nested types such as std::span<int>::size_type are no longer treated as containers.
- Member functions of containers called through smart pointers (e.g. m->find(i) where m is a std::shared_ptr<std::map<int, int>>) now get a value type, so 'auto' variables initialized from them are no longer untyped (#13105).
- Iterators to containers owned by smart pointers (e.g. v->begin() where v is a std::shared_ptr<std::vector<int>>) are now tracked. invalidContainer, derefInvalidIterator and mismatchingContainers (for std::unique_ptr) now detect bugs with such iterators.
- mismatchingContainers now detects iterator ranges from different containers passed to container member functions, e.g. s.insert(a.begin(), b.end()), v.insert(v.end(), a.begin(), b.end()), v.assign(a.begin(), b.end()) and str.append(a.begin(), b.end()).
